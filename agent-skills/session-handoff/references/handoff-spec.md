# 交接文档规范（`handoff-spec`）

本文件是 `session-handoff` skill 的**规范唯一权威**：格式、字段、编号契约、阈值数字都只在这里定义。
生成流程的可执行命令与自检片段在 `generate-playbook.md`，接手流程在 `resume-playbook.md`；
本文件**不重复任何可执行片段**，只给规则与指针。

## 文件名与归档

- **仓库根交接件**：`<前缀>_NEXT_SESSION_PROMPT.md`。**一律带前缀，无例外**（不允许无前缀的 `NEXT_SESSION_PROMPT.md`，多单元同仓靠前缀区分）。
- **历史归档**：`.dsh/handoffs/<前缀>_<YYYYMMDD-HHMMSS>.md`；同名同前缀的旧件按时间戳逐个归档，**不覆盖**。
- **归档保留数**：**只保留最近 20 份**，超出删最旧（裁剪命令见 `generate-playbook.md`「自检命令」）。
- **归档目录入 `.gitignore`**：`.dsh/handoffs/` 不进版本库；仓库根的 `<前缀>_NEXT_SESSION_PROMPT.md` **不**被忽略（它是要提交、要传递的交接件，见本文件「自指说明」）。
- 归档目录若不存在，**先创建**（`mkdir -p .dsh/handoffs`，见 `generate-playbook.md` 步骤 5）。

## 头部 YAML 元数据

交接件**首行**是 `---` 开头的 YAML 块，字段如下（值一律加引号，时间戳用字符串）：

| 字段 | 类型 | 来源（怎么取） |
|---|---|---|
| `generated_at` | 字符串 `YYYY-MM-DD HH:MM:SS` | 生成时刻的实测时间，不凭记忆 |
| `prefix` | 字符串 | 本文件「前缀命名与归档规则」选定的前缀 |
| `cwd` | 字符串（绝对路径） | 生成会话的工作目录 |
| `repo_root` | 字符串（绝对路径） | `git rev-parse --show-toplevel` 实测 |
| `git_head` | 字符串（短哈希） | `git rev-parse --short HEAD` 实测 |
| `git_branch` | 字符串 | `git rev-parse --abbrev-ref HEAD` 实测 |
| `goal` | 对象或 `null` | `get_goal` 实测；对象含 `objective` / `id` / `revision` 三键 |
| `other_units[]` | 数组 | 同仓其他单元的索引表，每项 `prefix` / `path` / `generated_at` / `one_line_status` |
| `archive` | 对象 | `dir`（归档目录）+ `retained`（本次裁剪后的实际份数） |

- `goal` 为 `null` 是**正常分支**（无 goal 的会话），此时前缀走「本会话主线提炼」，不报错、不阻断。
- `other_units` 缺失（本仓只有本单元）时写空数组 `[]`，不要省略该键。

## 勘误回写块（不编号）

- **位置**：头部 YAML **之后**、`§0` **之前**；**不编号**（它不是 `§` 小节，不参与编号顺序与预算）。
- **形状**：一段引用块或列表，每条 = **日期 + 证据（实测命令输出 / 文件路径）+ 修正内容**；指出被修正的原小节。
- **可累积**：新条目往后追加，**原文不删不改**，让读者看到「当时写的 → 后来实测的」。
- **格式**由本文件定义；**写回时机**（谁在读文档的哪一步回写）由 `resume-playbook.md`「勘误回写规则」定义，两处不重述对方内容。

## §0–§9 职责表

编号含义固定如下（**省略小节不重排编号**，无内容宁可省略）：

| 编号 | 职责 | 行数约束 / 写法约束 |
|---|---|---|
| `§0` | 你的第一件事（＝可直接粘贴的启动块） | ≤10 行；必须写明「先加载 `session-handoff` 的接手模式」、必读文件、不得重开事项、第一步动作 |
| `§1` | 客观事实基线 | **紧凑表**，逐项 ≤2 行 + 指针；`git status` 全文放不编号附录，不粘贴在正文 |
| `§2` | 最高优先级任务清单 | P0–P2 分级；每项必须带**可判定标准**与**前置条件闸门** |
| `§3` | 本会话已完成的工作 | **≤5 行摘要**（结论 + commit/文件指向）；详细过程与时间线进不编号附录 |
| `§4` | 已裁决与权威四层 | 关键裁决**附用户原句**；只存在于对话且未落盘者标 `[仅对话原文·未落盘]` |
| `§5` | 待办与开放项 | 含「**需你裁决**」清单，明确写清需要谁裁决 |
| `§6` | 已排除的死路与已证伪的假设 | **不限行数**（不计预算）；写「试过什么、为什么不行、什么条件下可重开」 |
| `§7` | 历史坑与硬约束 | **不限行数**；**按代价排序**（害我们绕最久的排最前） |
| `§8` | 关键文件索引 + Runbook 速查 | **不限行数**；引用式（落盘 Runbook 路径）+ **内嵌继续工作必需的关键命令** |
| `§9` | 一句话开启方式 | 面向**人**的一句可直接对模型说的话；与 `§0` 的分工见本文件「§0 与 §9 的分工」 |

**禁止漂移说明**：任何一节都不得把非本节职责的内容塞进来 —— 尤其 `§1` 不得变成时间线、`§3` 不得变成过程日志（过程进不编号附录）、`§6` 与 `§7` 不得合并（前者是「试过不行」，后者是「踩过的坑与硬约束」）。

## 不编号附录

放在所有编号小节之后，**不参与预算**、**不影响编号**，包含三类内容：

1. **详细过程与时间线**（被 `§3` 摘要掉的部分）；
2. **`git status` 全文**（`§1` 只放摘要与指针）；
3. **未核实项清单**（哪些断言取不到证、需要谁来核实）。

## 编号契约

1. **`§0`–`§9` 是本 skill v1 的固定契约**，**不与 2026-09 之前的历史交接件编号兼容**：历史件里 `§6` = 历史坑与硬约束、`§7` = 关键文件索引、`§8` = 方法论；本契约里 `§6` = 死路、`§7` = 历史坑、`§8` = 索引 + Runbook。差异清单见 `examples-and-pitfalls.md`「与 §0–§9 契约的差异」。
2. **省略小节不重排编号**，**禁空壳小节**：某一节无内容就整节省略，后面的编号**保持原值**，不得上移填空。
3. **新增编号只能 ≥ `§10`**，且必须置于**不编号附录之前**；`§9` 永远是最后一个编号小节。
4. **下游引用风险**：若被替换或重写的历史件其 `§N` 已被其他文档按旧编号引用，生成时**必须提示作者同步更新引用**；外部仓实证见 `research/handoff-history-audit.md:195-196`（`mcu-hil/AGENTS.md` 按 `§2 裁决 2`、`§6 第 2 条`、`§4 P2` 引用历史件编号）。
5. `§6`–`§8` **可以整节省略**（例如没有死路时），且**不计入**篇幅预算。

## 篇幅预算

- **`§0`–`§5` + `§9` 合计 ≤ 100 行**。
- **`§6`–`§8`** 与 **不编号附录**、**勘误块**、**头部 YAML** **不限行数**。
- **计数口径**：只计 `§0`–`§5`/`§9` 各节标题行**之后、下一个标题行之前**的正文行（含空行），**不含标题行本身**；这里的「下一个标题行」指**任何级别的标题**（`##`/`###`…），因此**不编号附录的标题会终止计数**——附录正文一律不计（实测坑：只认 `§N` 标题的实现会把附录整段算进 `§9`，造成假 FAIL）。`§6`–`§8` 与不编号附录的正文**不计**。
- **实测命令**：`generate-playbook.md`「自检命令」里的 `check-sections.sh`（同时校验编号齐全与有序、输出 `budget(...) counted=N limit=B`）。**本文件只定义数值与口径，不放命令**。
- 已知张力：`§1` 事实基线天然长，但计入预算 → 缓解办法是紧凑表 + 指针，详情一律进不编号附录。

## 事实标记法

- `[已核实]`：**必须附证据**——命令输出片段或文件路径；只写标记不给证据等同于没核实。
- `[仅记忆]`：未取证的断言，**不得在 `§4` 当裁决依据**。
- 关键裁决**必须引用户原句**（引号原样）；若该裁决只存在于对话、从未落盘，仍引原句但标 `[仅对话原文·未落盘]`，并在自检报告里建议用户落盘。
- 无标记的关键事实断言视为**违规**，自检清单里有对应检查项。

## 权威四层

裁决与陈述的优先级，从上到下：

1. **已裁决不得重开**：用户已明确裁决的事项，接手方不得重新讨论；要推翻必须由用户明确指示。
2. **已授权**：用户明确授权本次会话可以做的事（范围以授权原文为准，不得自行扩大或缩小）。
3. **未授权**：本方案未写明的一律视为未裁决，**不给加、不给改**。
4. **已否决**：用户明确否决过的事，**不得**换个说法复活。

## 前缀命名与归档规则

> 本节是前缀规则的**唯一权威**；`generate-playbook.md` 只写「按本节提名并展示确认」这个动作，不复制规则文本。

- **提名顺序**：① goal 关键词 → ② 无 goal 则从本会话主线提炼 → ③ 仍不明确则**问用户**。
- **绝不静默使用无信息前缀**（如 `main`、`handoff`、`session`、`temp`）。
- 生成前**向用户展示 nominee 并允许修改**；用户改了就按用户的写，不要二次猜测。
- 前缀进两处名字：仓库根 `<前缀>_NEXT_SESSION_PROMPT.md` 与归档 `.dsh/handoffs/<前缀>_<YYYYMMDD-HHMMSS>.md`。
- **写入前记录目标文件当前哈希**：发现同前缀文件已被其他会话改过（哈希与记录不一致）→ **报告用户、不静默覆盖**（多单元同仓的并发写保护）。

## 聚焦模式

- **触发**：用户指定只交接某条支线 / 某个前缀 / 某个范围（不是整仓全部活跃单元）。
- **被聚焦支线**：按常规完整书写（`§0`–`§9` + 附录）。
- **其余支线**：**不展开**，但在头部 YAML 的 `other_units[]` 索引表里**各列一行**，每行必须恰好这四个字段：

  | 字段 | 内容 |
  |---|---|
  | `prefix` | 该单元的交接件前缀 |
  | `path` | 该单元交接件在仓库内的路径 |
  | `generated_at` | 该件自身的生成时间（不是本次生成时间） |
  | `one_line_status` | 一行状态（在做什么 / 卡在哪 / 是否已完成） |

- **未指定聚焦时**：`other_units[]` 仍要列**全部**同仓单元（同前缀发现用**全树** glob，见 `generate-playbook.md` 步骤 1；仓库根同前缀文件的存在性必须用显式 `ls` 判定，不得用 glob 的返回值代替）。
- **自检项**：聚焦模式下，索引表行数 = 其余活跃支线数（少一行即为遗漏）。

## §0 与 §9 的分工

两节**面向对象不同**，禁止写成同义重复：

- **`§0` 面向下一个 agent**：可直接粘贴的启动块 —— 含「先加载 `session-handoff` 的接手模式」、必读文件、不得重开事项、第一步动作。写给机器执行。
- **`§9` 面向人**：一句话开启方式 —— 一句可以直接对模型说的话，交代「读哪份文档 + 当前状态 + 要什么产出」。写给人转述。

## 自指说明

- 生成模式产出的仓库根 `<前缀>_NEXT_SESSION_PROMPT.md` **会出现在它自己的 `§1` 里**（`git status` 会把它列为未跟踪文件）。规则：`§1` 必须把本次自生成的交接件**明确标注为「本次自生成，非待处理改动」**，避免继任会话把它当成需要处理的脏改动。
- **基线计数必须写明口径**：`§1` 里任何「计数类」断言（`git status --short` 行数、`find "*_NEXT_SESSION_PROMPT.md"` 结果）都要写清**是否包含本件自身**。推荐做法：给出**含本件自身**的实测值，并紧跟一句「含本件自身 1 项」。理由：本件在自己生成后才存在，生成前的实测值必然与接手方复跑的结果差 1，不说口径就会被判成「基线被别的会话改过」。
- **`other_units[]` 与「本仓是否存在交接件」是两件事**：`other_units[]` 只列**其他单元**的交接件；而 `find` 类断言会返回**本件自身**。`§1` 不得写成「本仓不存在任何 `*_NEXT_SESSION_PROMPT.md`」——本件就是一个。正确写法是「除本件外，本仓无其他 `*_NEXT_SESSION_PROMPT.md`」。
- 该文件**不加入 `.gitignore`**：交接件是要提交、要传递的产物（归档目录 `.dsh/handoffs/` 才是被忽略的那一侧）。
- 同理，若本次生成还改动了 `.dsh/handoffs/` 之外的规划文件，`§1` 也要区分「本次自生成」与「前序会话遗留」。
