# 实例与反例（`examples-and-pitfalls`）

本文件只做两件事：**给真实历史骨架做参照**、**列竞品失败模式当反例**。
规则与阈值仍以 `handoff-spec.md` 为准，本文件不定义规则。

## 与 §0–§9 契约的差异

历史件的编号含义与本 skill v1 契约**不同**，照旧编号去读会读错：

| 历史件编号含义 | 本契约（v1）对应 |
|---|---|
| 历史 `§6` = 历史坑与硬约束 | → 契约 `§7` |
| 历史 `§7` = 关键文件索引 | → 契约 `§8`（索引 + Runbook） |
| 历史 `§8` = 方法论摘要 | → 契约**无对应小节**；方法论并入 `§7`（历史坑与硬约束）与全局原则 |
| 历史 `§9` = 一句话开启方式 | → 契约 `§9`（含义一致，指向人） |
| 契约新增/改名 | `§6` 改为「已排除的死路与已证伪的假设」（历史件没有独立死路节） |

- 契约细节见 `handoff-spec.md`「编号契约」。
- **换用新编号时的事实风险**：历史件的 `§N` 可能已被下游文档引用。本仓之外的实证：`research/handoff-history-audit.md:195-196` —— 外部仓 `mcu-hil` 的 `AGENTS.md` 硬约束表按 `§2 裁决 2`、`§6 第 2 条`、`§4 P2` 引用其交接件。⇒ 替换历史件时必须提示作者同步更新引用。

## 竞品「不要这样做」清单

> 每条都写**完整仓库名 + 报告文件名 + 行号**。两份竞品报告各自给不同仓库编了**同名序号**，
> 所以本文件与 `handoff-spec.md` 一律不用「仓库 slug + 序号」式的局部标签，只写全仓库名
> （这正是本次审计纠正的引用问题）。

1. **靠文案 + 正则抠会话 id** —— `WeiYe6/dsh-session-handoff`（`research/competitor-dsh-handoff-plugins.md:255`、`:1127`）：子会话 id 从**命令结果文本**里正则抠出，并依赖 `SUCCESS_PREFIX` 成功文案；宿主改一个词，客户端就**静默失效**。
2. **依赖未承诺的内部 API** —— `Totoro-qaq/dsh-plugin-bridge`（`research/competitor-dsh-handoff-plugins.md:1192`、`:1133`）：从 `row?.projections?.values?.['title']` 里挖标题，报告内注释直陈「projection 形状随部署而异」（报告内引 `migrate.js:551`）——必然随版本漂移。
3. **文档级字符硬预算** —— `dongsheng123132/task-passport`（`research/competitor-dsh-handoff-plugins.md:871`）：`SUMMARY_CHAR_BUDGET = 2400` 把摘要锁死在约 900 token，适合"迁移即降 token"，不适合"交接要完整"。
4. **只注入会话内、不落盘** —— `WeiYe6/dsh-session-handoff`（`research/competitor-dsh-handoff-plugins.md:288-294`）：交接文档只作为新会话首条消息注入；README 自陈 `HANDOFF.md` 留作后续 ⇒ 不可审阅、不可 diff、不可版本控制。
5. **客户端 slot 名硬编码** —— `WeiYe6/dsh-session-handoff`（`research/competitor-dsh-handoff-plugins.md:243` `ctx.slots.inject('conversation.chat.node', …)`、`:1130`、`:1185`）：slot 名是 UI 内部命名，`0.1.2-alpha.1` 拆分会话 UI 已经把它打坏过一次（README 自陈），客户端半区成了升级痛点。
6. **没有强制取证机制** —— `WeiYe6/dsh-session-handoff`（`research/competitor-dsh-handoff-plugins.md:33`、`:281`）：全仓只有 system prompt 里一句 `do not invent facts`（报告内引 `lib/llm.mjs:17`），无 git 取证、无事实分级、不校验路径真实存在。
7. **「从未运行却报 clean」** —— `WeirdSky924/agent-handoff-skill`（`research/competitor-agent-handoff-skill.md:582`）：1.17.0 的 reverse-lint 步骤因 `git diff --name-only HEAD~N..HEAD` 把 `HEAD~N` 写成字面量（git 退出 128、循环体从不执行）而**每次安装都扫 0 个文件**，汇总表却把「never ran」写成「clean」，**两次**如此 ⇒ 本 skill 的自检**必须真跑并记录真实输出**。
8. **副本声明与实际不一致** —— `WeirdSky924/agent-handoff-skill`（`research/competitor-agent-handoff-skill.md:582`，1.19.0 条目）：同一版本号下，插件 cache 副本比源仓**多 53 行**且自称同一版本 ⇒ 本 skill 的分发快照与权威副本**必须逐字节一致并比对哈希**（见 `SKILL.md`「副本与同步」）。

## 引用纪律

- 本文件所有断言都必须带**完整仓库名 + 报告文件名 + 行号**；**禁止**使用「仓库 slug + 序号」式的局部标签——两份竞品报告各自把不同的仓库编成同一个序号，标签会让引用无法复核。
- 引用**外部仓源码**时同理：写清仓库名 + 文件路径 + 行号（例如上面的 `migrate.js:551`、`lib/llm.mjs:17`）。
- 摘录**只摘骨架与出处**，不复制长文；细节回原文读。
- 本文件的行号均按**核对当时的报告版本**；报告被更新后行号可能漂移，复核时以文件名 + 关键字二次定位。
