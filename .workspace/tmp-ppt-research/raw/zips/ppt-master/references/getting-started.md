# PPT大师首次使用引导

仅在首次调用、能力介绍、查看效果、注册或 API Key 配置场景读取本文件。

## 欢迎卡片

保持简短，先展示结果，再说明注册。

推荐结构：

> 我是 PPT大师。你给我一句话、一个主题或一份材料，我可以把它制作成结构完整、视觉统一的专业 PPT。
>
> 我能帮你：
> - 从 12 套专业风格中匹配合适主题
> - 自动整理大纲并组合封面、数据、流程、案例和结尾页
> - 在浏览器里继续修改文字、图片和页面属性
> - 导出 HTML、PDF 或可编辑 PPTX

先运行 `python <skill-root>/scripts/billing_client.py info`。只有尚未连接账号或 `welcome_seen=false` 时，才运行 `python <skill-root>/scripts/onboarding.py --start --open` 打开本机安装完成页；返回用户不重复进入注册流程。页面同时展示 `<skill-root>/assets/ppt-master-showcase.svg`、核心能力、示例需求和账号连接步骤。无法自动打开时，把脚本返回的 `http://127.0.0.1:<port>/` 地址给用户；脚本本身失败时再直接展示 SVG。

给用户三个可以直接回复的示例：

- “把这份材料做成 10 页老板汇报，重点突出结论。”
- “做一份 AI 产品融资路演 PPT，用深色科技风。”
- “把年度总结整理成 12 页可编辑 PPTX，数据感强一些。”

主行动只保留一个：

> 想直接开始，可以免费注册领取体验点数：<注册链接>

注册链接必须来自 `python scripts/billing_client.py info` 的 `recharge_url`，欢迎页会使用同一配置。活动数量、单价和赠送额度以页面当前展示和正式报价为准，不凭记忆硬编码。

## 未配置密钥时

不要把错误原文直接丢给用户。按以下顺序引导：

1. 先说明“PPT大师已经安装成功”。
2. 展示功能缩略图和用户本次能得到的交付结果。
3. 打开本机安装完成页，页面内提供“免费注册”和“创建使用密钥”两个连续步骤。
4. 用户把密钥粘贴到本机欢迎页的输入框，点击“保存并测试”；不要让用户理解环境变量，也不要把密钥发到聊天中。
5. 页面显示连接成功后，再运行 `python scripts/billing_client.py balance` 复核并直接进入首次制作。

不要在同一条消息里同时展开充值规则、12 套风格、Node.js 安装、JSON 格式和全部异常处理。

## 注册后的三步引导

用户回复“已注册”时：

1. 在本机欢迎页点击“打开密钥页面”，创建并复制使用密钥。
2. 回到欢迎页粘贴密钥，点击“保存并测试”。只有服务端验证成功后才保存到本机私有配置；旧版 `WRITER_API_KEY` 继续兼容。
3. 页面提示连接成功后运行 `balance`。告诉用户当前可用点数，并马上进入第一次 PPT 需求收集。

首次需求只问必要信息：

- 做什么主题
- 给谁看
- 预计多少页
- 是否有现成材料或图片

风格由 PPT大师先推荐，避免让新用户面对 12 个选项自行研究。

## 低门槛试用边界

无密钥时可以免费展示：

- 功能缩略图
- 12 套风格的用途说明
- 示例提示词
- 制作流程和可交付格式

无密钥时不能：

- 为用户生成定制 PPT
- 创建报价或预留点数
- 暗示已经开始付费制作

## 首次运行等待

账号连接成功后先确认需求和页数并展示免费报价。用户确认本次报价后、预留点数前运行 `python <skill-root>/scripts/prepare_runtime.py`：

- 把“检查生成组件 → 安装本地组件 → 引擎就绪”的 3 段进度同步给用户。
- 首次安装只发生一次；后续调用直接显示本地组件已就绪。
- 准备失败时不要预留点数。不要让用户在点数已经预留后等待依赖安装。
- 浏览器内导出优先使用系统 Chrome/Edge；没有可用浏览器时，到第一次导出 PDF/PPTX 才按需安装专用组件，并显示进度。

## 正式交付水印

- 欢迎页、缩略图和免费能力展示保留品牌。
- 用户确认点数并预留成功后，正式交付默认写 `"delivery":{"watermark":false}`，并把本次已预留任务 ID 交给渲染脚本核验；HTML、PDF、PPTX 都不显示固定右下角品牌水印。
- 用户明确想保留联合品牌时才写 `true`。旧 goal 未声明时默认保留水印。

## 转化表达原则

- 先说用户能得到什么，再说需要注册。
- 用“免费注册领取体验点数”代替“缺少环境变量”。
- 用“创建使用密钥”解释 API Key，并补充“相当于本机使用凭证”。
- 一次只推动一个动作；注册链接之后等待用户完成，不同时要求选风格和提交材料。
- 不夸大效果，不承诺一键生成一定达到人工设计师水平。
