# 9. 第二轮 · 物理布局修正（2026-09-30）

> **定性（协调者要求写明）**：本轮修复的是 **WP1 转换器的缺陷**，**不是 WP2 的落盘错误**。
> 第一轮落盘本身完全忠实——`cp -a` 逐字节复制、sha256 100% 相等、清单齐备；失效发生在**上游产物的物理帧布局**上。

## 9.1 失效原因（`[实跑]` + `[源码]`）

- **规则**：0.2.0 真实持久层要求日志**首帧恰好只有一行 header**（`[源码]` `$B/dsh-session-persistence-jsonl/lib/index.js:2293-2295`）。
- **惩罚**：`listArtifacts` 对该错误**静默 `continue`**（`[源码]` 同上 `:3040-3044`）⇒ 违反者不会报错，而是**整根枚举为空**（"看不见"）。
- **缺陷**：WP1 第一版 `convert.mjs` 把每份日志压成**单帧**（首帧含 header + 全部事件行）⇒ 首帧不是"恰好一行"。
- **本档独立复现（改前）**：`node p0a/framecheck.mjs $A/home/sessions` →
  `{"files":2524,"ok":16,"bad":2508,"frameCounts":{"1":2508,…}}`。
  **bad 2508 恰好 = 第一轮由我落盘的全部转换日志**（全部单帧）；`ok 16` 全是 3098 运行时产物。**逐条对应，无任何额外失败**。
- **修复后（WP1 已全量重转）**：`node p0a/framecheck.mjs $P/converted/sessions` →
  `{"files":2508,"ok":2508,"bad":0,"frameCounts":{"2":2508}}`（全部 2 帧）。

## 9.2 本轮动作（边界不变）

1. **定点覆盖落盘**：`python3 $P/deploy/wp2-overwrite.py`
   - 覆盖集合 = **`manifest-round1.jsonl` 登记过 ∧ 新 `converted/sessions/` 中存在的 `.zstd`** = **2508 条**（精确命中，多一条不碰）。
   - **未触碰**：16 个 `session.v4.jsonl.zstd`、16 个运行时 `session.lock`、本轮新出现的会话目录 —— 保持第一轮"保留并披露"口径。
   - 写入方式：**同目录临时文件 + `os.replace`**（同文件系统内原子替换），避免 0.2.0 并发读打开时看到半截日志。
   - 权限：覆盖后按源文件 `st_mode` 回设 **0664**（与 `cp -a` 语义一致；运行时产物仍为 0600，非本档所为）。
