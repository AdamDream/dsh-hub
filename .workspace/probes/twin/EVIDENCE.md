# adam 网关 `deepseek-v4.1-flash` vs `deepseek-v4-flash` 同体性判定报告

**判定日期**：2026-09-18
**被测网关**：`https://llmapi.roboscience.xyz/v1`（New API / QuantumNous 部署，Cloudflare + Caddy 前置）
**被测对象**：`deepseek-v4-flash`（下称 **A**）、`deepseek-v4.1-flash`（下称 **B**）
**对照**：`deepseek-v4-pro`、`deepseek-v4-flash-vision-exp`、`glm-5.3-flash`（异体阳性对照）、`qwen3.8-flash`

---

## 0. 结论（先说答案）

| 命题 | 判定 | 置信度 | 关键证据 |
|---|---|---|---|
| **A 与 B 是同一个底层模型的套皮** | **否（证伪）** | 高 0.85 | 上游部署不同（自报名、能力面、max_tokens 上限）；非思考模式下上下文 token 完全一致时仍 6/15 逐字节不同（同体基线仅 1/15）；思考模式首 token 分布 G=115（p≪0.001） |
| B 与 `deepseek-v4-pro`、`deepseek-v4-flash-vision-exp` 同体 | **是（证实）** | 很高 0.95 | 同一上下文下 top-5 logprob 向量**逐位相同**；采样分布同分布（G=5.99，不显著）；非思考模式 14/15 逐字节相同 |
| 该网关存在"名字与实体不对应" | **是** | 很高 0.95 | `deepseek-v4-pro` 的上游自报名就是 `deepseek/deepseek-flash`（flash 模型） |

一句话：**`deepseek-v4.1-flash` 不是 `deepseek-v4-flash` 的套皮；真正被套皮的是 `deepseek-v4.1-flash` / `deepseek-v4-pro` / `deepseek-v4-flash-vision-exp` 这三个名字——它们指向同一个上游实体。**

⚠️ 运维提示：`deepseek-v4-pro` 这个名字在这个网关上**实际服务的是 flash 级模型**（上游 slug `deepseek/deepseek-flash`，与 `deepseek-v4.1-flash` 逐位同分布）。若有按 pro 计费/按 pro 选型的用法，需要核对渠道配置。

## 1. 同源证据（说明 A、B 至少同族）

| 观测 | A (`deepseek-v4-flash`) | B (`deepseek-v4.1-flash`) | 结论 |
|---|---|---|---|
| 22 个异构探针的 `prompt_tokens` 差值 | — | 恒为 **+53** | 内容 tokenization 完全相同 ⇒ **同一 tokenizer** |
| filler 斜率（独立档实验，66 字符/行） | 15.000 行 | 15.000 行 | 同上（qwen 对照为 16.000，方法有效） |
| 专有特殊 token | `<\uFF5Cend\u2581of\u2581thinking\uFF5C>` | 同 | 同族 |
| `reasoning_content` / `thinking:{type:enabled\|disabled}` | 支持且生效 | 支持且生效 | 同族 reasoning 模型 |

> 恒定 +53 且与文本内容无关 ⇒ 不是不同 tokenizer（不同 tokenizer 的差值会随 emoji/CJK/数字/代码而变），而是**固定前缀/模板开销**。
> 补充：显式加 system 消息后差值仍为 53（short: 85 vs 32；long: 145 vs 92），说明这 53 token 是**无条件**开销，不是"缺省 system 提示词注入"。

## 2. 异体证据（说明 A、B 不是同一服务）

### 2.1 上游自报名（各 15/15 稳定，无抖动）

| 网关模型名 | 上游返回的 `model` |
|---|---|
| `deepseek-v4-flash` | `deepseek-v4-flash-0731`（带官方式日期版本号） |
| `deepseek-v4.1-flash` | `deepseek/deepseek-flash`（聚合商 slug） |
| `deepseek-v4-pro` | `deepseek/deepseek-flash`（同上） |
| `deepseek-v4-flash-vision-exp` | `deepseek/deepseek-v4-flash-vision-exp`（回显自身名） |

### 2.2 模板开销结构不同 —— 且差异**只存在于思考模式**

思考模式（默认）：

| 轮数 | A `prompt_tokens` | B `prompt_tokens` | 差值 |
|---|---|---|---|
| 1 | 84 | 31 | +53 |
| 2 | 86 | 35 | +51 |
| 4 | 92 | 41 | +51 |
| 8 | 104 | 53 | +51 |

**非思考模式（`thinking:{type:disabled}`）——差距完全消失**（`probe10.py` 串行干净批次，15 题无一错误）：

| prompt | A | B | `deepseek-v4-pro` |
|---|---|---|---|
| list | 17 | 17 | 17 |
| format | 22 | 22 | 22 |
| pie | 18 | 18 | 18 |
| sum | 17 | 17 | 17 |
| json | 24 | 24 | 24 |
| translate | 20 | 20 | 20 |
| unit | 19 | 19 | 19 |
| logic | 35 | 35 | 35 |
| date | 24 | 24 | 24 |
| sort | 32 | 32 | 32 |
| …（15/15 题全部相等） | | | |

**修正后的解释**：两条渠道的**基础 chat 模板与 tokenizer 完全一致**；恒定 53 token 的差额是 **A 渠道在思考模式下注入的 reasoning 脚手架**（官方侧 thinking 模板开销），而非"另一套模板"或"默认 system 提示词"。
同一段 61-token 的 system 文本在两渠道计费一致（+61），亦印证 tokenizer 相同。

> 这一发现同时是**混淆因素**：思考模式下 A 的上下文比 B 多 53 token 的推理脚手架，它**可能**是 A 的 reasoning 开头分布偏向 `We`（99% vs 57%）的原因之一，见 §3。

### 2.3 能力面/参数面对比（各 3 次复现一致）

| 观测项 | A | B | `deepseek-v4-pro` |
|---|---|---|---|
| `logprobs` | **不支持**（请求 200 但无该字段，12/12 稳定） | **支持**并返回数值 logprob | 支持 |
| `n=2` | 不报错，但**只返回 1 个 choice** | 报错/超时 | 报错/超时（与 B 完全一致） |
| `response_format=json_object` | 接受（200） | **HTTP 500「可用渠道不存在」** | **HTTP 500「可用渠道不存在」**（与 B 完全一致） |
| `max_tokens` 上限 | 接受到 2,000,000 | ≥990,000 即失败（**串行限速复测再次确认**：A=200 / B=500 / pro=500） | 同 B |
| `/v1/completions` | 上游 404（未实现） | 上游 404 | 上游 404 |
| `thinking:{type:disabled}` | 生效（无 reasoning，直接 content） | 生效 | 生效 |

> **修正**：早期表述"`n=2` A 接受、B 拒绝"不准确。串行复核（2s 限速，低负载窗口）显示 A 对 `n=2` 不报错但**只返回 1 个 choice**，B/pro 则报错或超时；`json_object` 一项 A 稳定 200、B/pro 稳定 500（两轮独立复现，同一窗口内 A 正常 ⇒ 非全局故障）。该轴上 **B 与 pro 再次完全一致**。

### 2.3b 非思考模式逐字节电池（串行限速，2 次/题，零错误）

关闭 thinking 后上下文 token 完全一致（§2.2），此时输出的逐字节差异只能来自权重/采样栈：

| 对比 | 逐字节相同题数 | 说明 |
|---|---|---|
| **`deepseek-v4-pro` vs B**（同体基线） | **14/15** | 仅 `math` 一题不同（B 给 `72.58333333333333`、pro 给 `72`）⇒ 同实体的固有抖动 |
| A vs B | **9/15** | `math` / `code` / `list` / `format` / `style` / `sort` 六题不同 |
| A vs `deepseek-v4-pro` | 9/15 | 同上六题 |
| 自身 2 次可复现 | A 12/15、B 13/15、pro 15/15 | 非思考模式基本确定 |

差异样例（同一题、同一上下文长度）：
- `format`（把 hello world 转大写并反转）：A 给 `DLO W OLLEH`（错），B/pro 给 `DLROW OLLEH`（对）
- `list`：A 给 `冒泡排序  \n快速排序  \n归并排序`（尾随双空格），B/pro 给无空格版
- `style`：A 给 `桂雨满城，湖山醉人。`，B/pro 给 `桂雨落满西湖，满城尽带桂花香。`
- `sort`：A 给 `[1, 1, 2, 3, 4, 5, 6, 9]`，B/pro 给 `[1,1,2,3,4,5,6,9]`

### 2.4 首 token 分布（决定性，两轮独立复跑）

同一逻辑提示（`hi`）、`temperature=1`、`max_tokens=1`、取首个 reasoning token：

| 模型 | 第 1 轮 N=200 | 第 2 轮 N=150 |
|---|---|---|
| A `deepseek-v4-flash` | `We` **197**（98.5%）, `The` 2, `Hi` 1 | `We` **149**（99.3%）, `Here` 1 |
| B `deepseek-v4.1-flash` | `We` **121**（60.5%）, `The` 50, `<end_of_thinking>` 23 | `We` **85**（56.7%）, `The` 37, `'`24 |
| `deepseek-v4-pro`（**同体基线**） | `We` **121**（60.5%）, `The` 51, `'`21 | `We` **79**（52.7%）, `The` 40, `'`25 |
| `deepseek-v4-flash-vision-exp` | — | `We` **90**（60.0%）, `The` 45, `'`9 |
| `glm-5.3-flash`（异体对照） | `Let` 200（100%） | `Let` 150（100%） |

G 检验（似然比）：

| 对比 | G | df | 结论 |
|---|---|---|---|
| B vs `deepseek-v4-pro`（同体基线） | **5.99** | 9 | **不显著**（p>0.001）⇒ 判为同分布 |
| A vs B | **115.06** | 8 | **极显著**（p≪0.001）⇒ 判为不同分布 |
| A vs `deepseek-v4-pro` | **114.98** | 8 | 极显著 |
| 任意 vs glm（异体对照） | 554.52 | — | 极显著 |

方法有效性自证：B 与 `deepseek-v4-pro` 在 logprob 层面已证明逐位相同，本检验对二者判"不显著"；对确定异体的 glm 判"极显著"。**检验既能判同也能判异**，因此对 A vs B 的"极显著"是有判别力的结论。

### 2.5 logprob 向量（未采样分布，最强证据）

同一上下文（`请用一句话说明什么是网关。`，`temperature=0`，`top_logprobs=5`）：

```
B  deepseek-v4.1-flash : ('我们需要', -0.0014, [我们需要 -0.0014, The -7.1515, We -7.5931, 用户 -9.3716, 我们 -11.0854])
   deepseek-v4-pro     : ('我们需要', -0.0014, [我们需要 -0.0014, The -7.1515, We -7.5931, 用户 -9.3716, 我们 -11.0854])   ← 逐位相同
   vision-exp          : ('我们需要', -0.0014, [我们需要 -0.0014, The -7.1515, We -7.5931, 用户 -9.3716, 我们 -11.0854])   ← 逐位相同
A  deepseek-v4-flash   : 无 logprobs（渠道不支持，无法比对）
```

`hi` 提示同理：B / pro / vision-exp 三者共享同一组离散向量族（`{-0.5862,-1.2451,-2.0509,-4.3286,-5.6154}`、`{-0.4726,-1.4707,-2.1574,-4.3342,-5.1558}`），且存在跨模型逐位相同的向量。7 个 `(token, logprob)` 向量精确匹配（如 `p_zh` 6/9 完全一致、`p_math` 4/9）。

> 不同权重不可能给出小数点后 4 位相同的 top-5 分布；这是"同权重"级别的证据。
> 该结论的另一种解释是：**该上游渠道忽略模型名、把所有别名都路由到同一个实体**——无论哪种，从网关使用者角度看，这三个名字就是同一个模型。

## 3. 方法学与可信度声明

- **判别器优先级**：logprob 向量（未采样分布）> tokenizer 指纹（恒定差值）> 大样本首 token 分布（G 检验）> 能力/参数面 > 逐字节文本对比（本场景因 reasoning 采样非确定性，单次文本对比证据力最弱）。
- **为什么不能直接比对 A 与 B 的 logprob**：A 所在渠道不返回 logprobs（15/15 + 12/12 稳定），已尝试 `/completions`、`logprobs` 整型/布尔变体、`echo` 等路径，全部无效。因此 A vs B 只能靠"大样本采样分布 + 模板 + 能力面"三条独立证据交叉判定，三者一致指向"不同实体"。
- **混淆因素已界定（部分关闭）**：A 在思考模式下恒定多 53 token 的 **reasoning 脚手架**（§2.2 修正），**可能**影响 reasoning 开头风格。§2.4 的分布差异（We 99% vs 57%）因此**不能单独**作为"不同权重"的终局证据。但两条旁证独立于该混淆：
  1. **非思考模式下上下文 token 完全一致**（无脚手架差异），A 与 B 仍有 6/15 逐字节不同，而同体基线（B vs pro）仅 1/15；
  2. 渠道级能力面差异（logprobs / n / json_object / max_tokens 上限）与权重无关，属于**不同上游部署**的直接证据。
  §4 中"注入 system 提示词看能否把 B 的 We 率推向 99%"的阴性/阳性对照因网关限流触发熔断而未跑完，该混淆项未 100% 关闭。
- **已知干扰**：本次探测的高并发请求曾触发网关 `503 分组 auto 下模型 X 的可用渠道不存在`（用户亦观察到频繁断联），导致部分批次（尤其 `zh` 提示词轮次）样本被截断；受影响数据已剔除或标注。决定性结论均取自无错误的干净批次（N=200/150，ok=100%）。**后续所有复测已改为串行 + 1.2s 限速 + 连续失败熔断**。

## 4. 温和复测（串行 + 限速 1.2s + 连续失败熔断）

- **非思考模式确定性电池**：15 题 × 3 模型 × 2 次，**零服务端错误**，结果见 §2.2 / §2.3b。
- **负载敏感结论复核**：`max_tokens=990000` 串行复测 —— A 返回 200（`deepseek-v4-flash-0731`），B 与 pro 均返回 500。**原结论成立，不是负载造成的假象**。
- **混淆界定实验（未完成）**：准备对 B 注入 3 组 system 提示词（含"强制以 We 开头"阳性对照），N=25 串行。网关在 `max_tokens` 复测后连续 6 次 5xx，**熔断器主动退出**，该实验未跑；`raw/E9_confound.json` 仅存基线（B 无 system 时 We 率 0.567 / A 参照 0.993）。
- 结论：本次只做了"温和但有限"的复测，避免再次打断网关；如需关闭 §3 剩余混淆项，建议在网关空闲时段、单请求串行的条件下补跑该对照实验。
