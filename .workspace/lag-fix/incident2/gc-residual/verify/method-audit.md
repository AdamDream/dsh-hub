# Method audit — `incident2/gc-residual` (paper/static, no browser launched)

- Auditor: independent measurement-methodology audit (delegated line), 2026-09-22
- Scope: `scripts/capture-gc.mjs`, `scripts/analyze-gc.mjs`, `tools/probe-lock.sh`, `tools/run-locked.sh`
- Method: static read of the four files + read-only machine evidence (`ps`, `/proc`, live `owner.txt` files, the
  peer trace fixture `incident2/user-capture/fixtures/real-settings-trace.json`, seven real CDP profiles under
  `incident2/first-open-profile/raw/`, and a shell experiment reproducing the pipeline exit-status bug).
- **No browser was launched; no node process was pointed at the GUI; the host process (10806) was only observed via `ps`/`/proc` reads.**
- Exclusivity caveat for the reader: this audit also observed that the machine is *currently* not exclusive
  (two foreign pipe-launched `headless_shell` browser processes at the time of reading, from sibling lines).

---

## (a) Verdict table

Legend: **PASS** = sound as designed; **NEEDS-FIX** = a concrete defect/biasing assumption that must be corrected
before the number may be used; **FAIL** = the measured quantity is not the intended quantity (deliverable cannot be
delivered by this instrument as written); **INCONCLUSIVE** = cannot be decided from the artifact as designed.

### A. Units and clock domains

| # | Check | Verdict | Evidence |

### B. Page clock ↔ node clock ↔ window boundaries

| # | Check | Verdict | Evidence |

Correct **only if** (a) the node↔page clock offset is negligible and (b) no navigation rebased `timeOrigin`. Both are unverified — see B1b. |
| B1b | Clock-offset and navigation guards | **NEEDS-FIX** | `capture-gc.mjs:295` defines `page2epoch` and `:296` computes `pageClockSkewMs`, and **neither is ever used** (dead code) — the mark uses a static `timeOrigin` with no skew correction, in a direction (`node − page`) that is the inverse of the helper's. | B2 | Heap series ↔ click/window boundaries | **PASS** | `capture-gc.mjs:390` `heap.filter(h => h.t >= tC−2000 && h.t <= tC+2000)` with `tC = wClick.action.tMark` (`:389`) and heap `t = Date.now()` (`:279`): same node-process clock domain. `:358` window-centre slice uses `(tStart+tEnd)/2`, also `Date.now()`. |
| B3 | The click window is actually `[click−2s, click+2s]` | **NEEDS-FIX** | `capture-gc.mjs:312-313`: the action is `await`ed **before** `sleep(ms)`, so the window length is `CLICK_PRE + clickLatency + CLICK_POST` (≥ 6000 ms, with `CLICK_PRE=CLICK_POST=2000` at `:40`) and the right edge is stretched by however long `clickSettings` took (up to 3 s per failed candidate, `:247`). ### C. The five-bucket definition

| # | Check | Verdict | Evidence |
|---|---|---|---|
| C1 | B1 `ScriptDuration` vs B2 `RecalcStyle+LayoutDuration` disjointness | **NEEDS-FIX** (systematic over-count) | `analyze-gc.mjs:94-95`, `:99` `sumA = b1+b2+b3+b4`, `:100` `b5 = task − sumA`. Style recalc and layout forced **from inside script** (`getComputedStyle`, `setProperty`, `offsetHeight`) execute within the JS frame; this line's own prior evidence is that `ThemePresenter.apply`'s profile self-time is **2.5–3.8× `ScriptDuration`** *precisely because* Blink's forced recalc is billed inside that JS frame (`research-v2/MEASUREMENT-STATUS.md:100`, `:126-129`; `exec-theme/report.md` §9/§6.3 boundary). So B1 ∩ B2 ≠ ∅ by construction; summing them inflates `sumExplained` and deflates (can invert) B5. Context for why this matters here: the residual this line is chasing was defined as exactly "散点 on the sampling table with no owner — `(program)`, GC, `no-url:native/vm`, React commit, connection layer" (`exec-theme/report.md:438-441`, §9 boundary statement), so the buckets are being aimed at quantities the prior line already knew were only visible as unattributed scatter. |
| C2 | B3 (PO `gc` ms) disjoint from B1/B2, and equal to main-thread GC cost | **INCONCLUSIVE** + **NEEDS-FIX** | `analyze-gc.mjs:96` `b3 = w.gcPage.totalMs`. (ii) A GC triggered by allocation inside script is likewise inside the script frame ⇒ B1 ∩ B3 cannot be shown empty. The code acknowledges the possibility only as a *variant* (`analyze-gc.mjs:101` `sumB = b1+b2+b4`), but variantB still keeps B2, so it does not remove the overlap — it only removes GC. | C3 | B4 name set vs the categories actually enabled | **FAIL** | `capture-gc.mjs:33` `CATS='devtools.timeline,blink.user_timing,v8,disabled-by-default-v8.gc'` vs `:118` `PC_RE` = `Paint|PaintSetup|Commit|CompositeLayers|Layerize|RasterTask|GPUTask|ImageDecodeTask|DrawLazyPixelRef|PaintImage|Rasterize`. | C4 | Main-thread identification in the trace | **FAIL** | `capture-gc.mjs:181-191` picks `mainTid` = the `pid:tid` with the most `RunTask` events; `:201` then discards every event whose thread ≠ `mainTid`. With `runByTid` empty, `main = null` ⇒ `mainTid = null` ⇒ `k !== null` for every event ⇒ **all events dropped**: `paintCompositeUnionMs = 0`, `gcMainCount = 0`, `mainAllUnionMs = 0`, `runTaskUnionMs = 0`. `integrity.traceParsed` (`:361`) is false, but the only consequence is a log line (`:506`) — `analyze-gc.mjs:97` then sees `paintCompositeUnionMs === 0` (**not `null`**) and uses it as a *measured zero*: `b4 = 0`, `sumA` unchanged, and 100% of main-thread paint is pushed into B5. Secondary: even with the category fixed, the max-count heuristic is unverified against the actual page renderer — in the real trace the renderer main thread (3183 RunTask) beats the browser UI thread (2475) by only 1.29×, and nothing maps a pid to *this page*. |

### D. Profile side

| # | Check | Verdict | Evidence |
|---|---|---|---|
| D1 | Self-time aggregation given the `samples[i]` / `timeDeltas[i]` pairing | **PASS** (with a cheap assertion missing) | `capture-gc.mjs:136-141` pairs `timeDeltas[i]` with `samples[i]` and sums per node — this **is** the CDP/DevTools convention ("self time of sample *i* = delta *i*"), and the empirical check above confirms the pairing is structurally consistent (`samples.length == timeDeltas.length` in 7/7 profiles; Σ Δδ = elapsed span). ### E. Exclusivity, ownership, lock protocol

| # | Check | Verdict | Evidence |
|---|---|---|---|
| E1 | `run-locked.sh` actually refuses to launch when the lock is not acquired | **FAIL (highest severity)** | `tools/run-locked.sh:5` sets only `set -u` (no `pipefail`), and `:12` is `bash …/probe-lock.sh acquire gc-residual 2>&1 \| tee -a … \|\| { echo "LOCK NOT ACQUIRED …"; exit 3; }`. A pipeline's status is `tee`'s, so the `||` guard **can never fire**: `probe-lock.sh`'s `exit 2` TIMEOUT (`probe-lock.sh:37`) is swallowed. Reproduced in this session: `( exit 2 ) 2>&1 \| tee f; echo $?` → `0`; with `set -o pipefail` the same line returns `2`. The same masking applies to the release at `run-locked.sh:33`. |
| E2 | The capture script gates on the lock / foreign instances | **FAIL** | `capture-gc.mjs:281` / `:479` call `censusNow()` and only **log** the result (`:284`, `:480`); `lockHeldByLine` (`:87`) and `foreignCount` are recorded into the JSON but **nothing is asserted**, and `chromium.launch` (`:481`) is unconditional. There is no `--nolockwait`-style bypass to blame; the bypass is the absence of any gate. Combined with E1 this makes "ran without exclusivity" silent and reachable on the first attempt. |
| E3 | Per-window exclusivity gating | **NEEDS-FIX** | Census exists only at load start (`:281`) and load end (`:406`) — never per window, although each window is 8–10 s (`:40`) and the discipline requires before/after gating per window with `invalid` marking (`research-v2/MEASUREMENT-STATUS.md:28-31`). Note the sibling line's own report that even a *held* lock coexisted with 18–31 foreign processes (`:16`), and the observation made during this audit (2 foreign pipe-browsers). |
| E4 | The recorded owner pid is a live process for the duration of the hold | **FAIL** | `tools/probe-lock.sh:23-24` writes `pid=$$` — but this script is invoked as `bash tools/probe-lock.sh acquire` from `run-locked.sh:12`, so `$$` is the **short-lived shell that `exit 0`s at `probe-lock.sh:25`**. The lock's owner pid is therefore *already dead within milliseconds of acquisition*, while the campaign + browsers run for minutes. A sibling implementation on this machine preempts on **pid absence alone, with no age gate**: `incident2/headed-vs-headless/run-campaign.sh:39-43` (`opid=$(sed -n 's/.*pid=\([0-9]\+\).*/\1/p' …)` then `[ ! -d "/proc/$opid" ]` ⇒ `rm -rf "$SHARED_LOCK"`), against the same lock dir (`:8` = `research-v2/.probe.lock`). ⇒ that line will steal this line's lock on its first poll while our browser is live. That same script also releases **unconditionally** (`:51` `release_shared() { rm -rf "$SHARED_LOCK"; }`) and removes the shared lock in a `trap … EXIT` (`:52`) regardless of ownership, so it can delete *our* live lock even without the pid path. Concrete machine evidence that dead-owner locks are the norm here: the live `research-v2/.probe.lock/owner.txt` records `pid: 40338` (peer format) and `/proc/40338` **does not exist** while the directory remains held; our own wait log shows the peer's pid changing every ~30 s (`logs/gcrun-1020.lock.log`). And a lock *being taken from a live holder* is not hypothetical on this machine — the sibling cpu-profile line records exactly that: "16:13 我持有的锁被他人移除（我从未 `rmdir`），owner 于 16:14 变为 `measure-hardening`。**违反"仅在 owner 超 25 分钟且进程不存在时才可抢占"**" (`research-v2/cpu-profile/audit.md:139`, 协议缺陷 A). |
| E4b | Census unit (which processes count as "foreign browsers") | **PASS with a stated hole** | `capture-gc.mjs:43-62` implements the agreed unit verbatim — "含 `--remote-debugging-pipe` 且不含 `--type=`" (`research-v2/cpu-profile/audit.md:203`, `0bis.1`) — which correctly avoids the 5–8-children-per-instance inflation of `pgrep -c -f headless_shell` (same line). No port-launched browser was observed during this audit (2 foreign pipe-launched `headless_shell` browser processes were). |
| E5 | owner.txt parsing across the formats in use | **NEEDS-FIX** (partly PASS) | The **two named formats parse correctly** — verified live against all four real files: regression format (`incident2/regression/tools/firstopen-ab.mjs:73`: `agent: …` + `pid: 57756` + `started_at: …Z`) → `opid=57756`, `age=24s` ✓; this line's own format (`pid=N` + `ts=<local ISO>`) → ✓. **But two further formats in live use on this machine are mis-parsed**: `incident2/headed-vs-headless/.lock/owner.txt` = `pid=42910 started=2026-09-22T10:18:13+08:00 purpose=headed-vs-headless` (single line, from `run-campaign.sh:18`) and `incident2/first-open-profile/owner.txt` = `pid=18998 ts=… owner=… line=… dir=…`. | E6 | Release order and leftover-file behaviour | **NEEDS-FIX** (order itself correct) | `probe-lock.sh:45-46` (`rm -f owner.txt` then `rmdir`) **is** the order the sibling line found necessary and wrote into the protocol after hitting the bug (`research-v2/cpu-profile/audit.md:141`, 协议缺陷 B: `rmdir` fails silently on a non-empty directory). The residual defect is what happens when `rmdir` fails anyway: the directory is left **without `owner.txt`**, and every future `acquire` then reads `opid=`/`ostart=` empty ⇒ `alive=no`, `age=?` ⇒ the gate at `:32` is false forever ⇒ **no line on the machine can ever acquire again**; `run-locked.sh:33` does not even surface the failure (tee, E1). |

## (d) Claims this line must NOT make with this instrument

1. **Any absolute ms, ms/s, or "% of main thread" figure for the GUI** — including the framing "≈65-100 ms/s unattributed". The machine has not been exclusive (MEASUREMENT-STATUS §1, §2.1.5) and this harness has no per-window gate (E3).
2. **"B5 is the non-GC residual / (program) cost"** — B5 is a plug figure over non-disjoint buckets (C1/C2), can be negative (C7), and silently absorbs paint when the trace or the main-thread key fails (C4/C8).
3. **"paint/composite is X % of main-thread time"** — as configured, B4 can only contain `Paint`+`Layerize`; in the failure path it is exactly 0 (C3/C4).
4. **"GC is X % of main thread" derived from the profile's `(garbage collector)` class**, and **any equation between PO gc ms, trace GC ms and profile GC share** — three different quantities, one of them 4.3-7.8× inflated by nesting (C6) and another quantized to a single node (D3).
5. **"cold-open costs X"** — the cold window starts after DOMContentLoaded (B4).
6. **"the settings click costs X ms / X ms/s"** — the window is `[click−2 s, click+2 s+latency]` and includes the harness's own selector scan (B3, F6).
7. **"exclusive / uncontended measurement"** on the basis of the lock — the lock can be stolen on pid-absence alone (E4) and the launch proceeds even when acquisition fails (E1/E2).
8. **"`(program)` is Blink C++ / V8 builtin"** as a mechanism statement — the class split cannot distinguish those, and the §11 correlation intended to decide it is INCONCLUSIVE (F9).
9. **Anything derived from §11 correlations, or from §10 means that include windows with `null` buckets** (C8, F9).
10. **Comparability to earlier batches** (the 65-100 ms/s residual, the 50-80 % `apply` share) until S1-S5 are fixed and a per-window gated run exists; the instrument today changes the numbers by construction (S5 alone moves `TaskDuration` by the parse/flush tail).
11. **The "65–100 ms/s residual" as a target or acceptance baseline.** It is an extrapolation from the **contaminated** batch `cpuL`, stated in its own words: "按 `cpuL` 的 `home-idle`（busy 130.0 / apply 65.4 ms/s）估算残留 ≈ **65 ms/s**… ≈ **100 ms/s**" (`exec-theme/report.md:438-439`), while the same line quantifies the contamination inflation on that same batch as Task ms/s **3.2–8.3×**, Script **4.5–10.3×**, `apply` **9.6–20.5×** (`research-v2/cpu-profile/audit.md:133-140`, §0bis.4) and labels all its absolute ms (b)-class INCONCLUSIVE. A new instrument that produces a different residual must therefore not be validated, tuned, or "confirmed" against 65–100 ms/s; the only admissible reference is an exclusivity-gated, same-harness measurement.
