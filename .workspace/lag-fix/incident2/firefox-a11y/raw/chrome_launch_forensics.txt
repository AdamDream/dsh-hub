 HYPOTHESIS VERDICTS

 H1 "it came from an ENVIRONMENT VARIABLE"  -> NOT SUPPORTED
    * Mechanism: a process's /proc/<pid>/cmdline is the argv passed at exec(2). An
      environment variable cannot insert a token into argv. A wrapper would have to
      expand one explicitly, and the only Chrome launcher wrapper on this host does
      not: /opt/google/chrome/google-chrome is 30 lines and was read in full; its
      exec line is literal, with no variable expansion:
         exec -a "$0" "$HERE/chrome" "$@" --force-renderer-accessibility
    * The a11y env vars that DO exist on this host are GTK/Qt-level, not Chromium's:
         /etc/environment            : ACCESSIBILITY_ENABLED=1 ; GNOME_ACCESSIBILITY=1
         /etc/profile:41-42          : export ACCESSIBILITY_ENABLED=1 ; export GNOME_ACCESSIBILITY=1
         /etc/environment.d/90atk-adaptor.conf : GTK_MODULES=${GTK_MODULES:+$GTK_MODULES:}gail:atk-bridge
         /etc/environment.d/90qt-a11y.conf     : QT_ACCESSIBILITY=1
      and GTK_MODULES is ABSENT from the Chrome binary, so Chrome does not consume it.
    * Note for completeness: /etc/environment lines are written with an "export "
      prefix inside ##TEC_BEGIN##/##TEC_END## markers. /etc/environment is parsed by
      pam_env as NAME=VALUE pairs, so an "export X=1" line does not define a variable
      named X there (the effective copy is the one in /etc/profile, which IS a shell).
      This makes the ACCESSIBILITY_ENABLED/GNOME_ACCESSIBILITY injection largely
      vestigial via pam_env - it does NOT put the Chromium switch into any argv.

 H2 "it came from a POLICY FILE"  -> NOT SUPPORTED
    /etc/opt/chrome/policies/ and /etc/chromium/policies/ do not exist. The host's
    only policy machinery is a managed endpoint agent (/etc/.OCular/), and
    grep -ril -E 'chrome|accessib|renderer-accessibility' over
    /etc/.OCular/Policy/, policy.xml, config.xml, Agent.conf, SDConfig.xml
    returned NO hits -> no policy references Chrome or accessibility.

 H3 "it came from a DESKTOP-FILE Exec LINE"  -> NOT SUPPORTED (for this PID)
    * Both Chrome desktop files carry a plain Exec with no flag (see B2 items 3-4).
    * Timing/argument-shape evidence rules the wrapper path out for pid 303448:
        - the wrapper appends the flag LAST, after "$@"; pid 303448 has the flag
          FIRST and --ozone-platform=x11 second;
        - the wrapper also sets argv[0] to the invoking path via `exec -a "$0"`,
          but pid 303448's argv[0] is the real binary /opt/google/chrome/chrome;
        - the wrapper never adds --ozone-platform=x11, which pid 303448 does have.
      => pid 303448 was exec'd directly as
         "/opt/google/chrome/chrome --force-renderer-accessibility --ozone-platform=x11".
