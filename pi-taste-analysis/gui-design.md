## 0. 核心裁定：A（Typert Remote）vs B（connection.rpc.handle）

### 0.1 结论

选 **B**：`ctx.connection.rpc.handle("/taste", handler, { authority: "loopback" })` + client `ctx.get("connection").rpc.call("/taste", endpoint, payload)`。

A（TypertRemoteService Remote）在本部署**不可用**——不是"可用但不推荐"，而是**缺少生成面**。排他性证据如下。

### 0.2 A 不可用的排他性证据（源码）

**(a) Typert 的远程面是"生成器产物"，不是运行时 API。** `dsh-goal` 是官方唯一用 `TypertRemoteService` 暴露 `remote.goals.*` 的包，其主机面与客户端面两个文件首行都写着：

- `<web>/dsh-goal/lib/typert.host.js:1` → `/* Generated by @deepseek-ai/dsh-typert-generator from FaceModel — do not edit. */`
- `<web>/dsh-goal/lib/typert.remote-client.js:1` → `/* Generated by @deepseek-ai/dsh-typert-generator from the Host FaceModel — do not edit. */`

这两个文件是**编译产物**（zod v4 schema 常量 + `TYPERT`/`TYPERT_REMOTE` 描述符表），由官方构建管线里的 `@deepseek-ai/dsh-typert-generator` 产出。本部署**无源码 checkout、无官方构建管线、无 dev watcher**（任务约束），该生成器根本不存在于运行时依赖树中。

**(b) 即使手写，`TypertRemoteService` 基类本身不做任何线缆连接。** `<web>/dsh-typert-protocol/lib/index.js`：

- `:53-66` `TypertRemoteService extends Service`——构造时只 `super(ctx, serviceKey)` + `this.typertRemote = bindTypertRemote(this, this.name, options)`，得到一个**冻结的绑定描述对象**，不向任何 RPC 通道注册任何东西。
- `:67-76` `Remote` 装饰器只往私有 `WeakMap` 打 marker；`:99-106` `remoteMethods()` 读 marker。注释原话 `:5-6`："Strict reflection remains a Typert compiler responsibility."（严格反射是编译器职责）。

**(c) 真正把 `remote.goals.*` 接通的是"loader + gateway + 编译进 api-remotes 的描述符"三层，缺一不可：**

1. **host 面注册**：`<web>/dsh-typert-loader/lib/index.js:40` `TYPERT_HOST_EXPORT = "./typert"`；`:57-67` `typertExportOf` 要求包 `exports["./typert"]` 指向 `TYPERT` manifest；`:77-118` `validateTypertManifest` 做**严格校验**——要求 zod v4 schema 携带内部 `_zod` 标记、`model.services/types/events/objects` 完整反射、每个 invocation 的 `sourceLocation`、strict codec 的 `typeSymbol`。`:218-326` `apply` 扫描 loader 条目并 `ctx.typert.register(manifest)`。**没有生成器就没有这些 manifest。**
2. **client 面挂载**：`<web>/dsh-api-remotes/lib/client.js:6043-6068` —— `inject = ["remote"]`，`apply` 里对 **7 个硬编码的 `TYPERT_REMOTE$N` 常量**逐个 `ctx.remote.$mount(contribution)`。`:4309-4389` 可见 `namespace:"goals"` 的描述符是**编译死在 api-remotes 客户端 bundle 里的**。要新增 `remote.taste` 只能改官方 `dsh-api-remotes` 包（红线：零官方包改动），或自己手写等价描述符并 `ctx.remote.$mount`。
3. **host 面 gateway**：`<web>/dsh-base/cordis.patch.yml:30-37` 加载 `typert`(registry)、`typert-loader`、`typert-gateway`(`dsh-api-gateway`)——gateway 依据 invocation 的 `scope:{context:"agent"}` + `lookup:"agent"` 参数做 **agent 身份解析路由**（`dsh-api-remotes/lib/index.js:150-166` `configureHost("agent", resolveAgent)`）。taste 是**无会话维度的只读文件数据**，本就不适配 agent-lookup 路由模型，强行套用需为每个方法伪造一个 `agentId` lookup 参数。

**结论**：A 方案需要 ①不存在的生成器 ②手写 `./typert`/`./remote` 两个 manifest + zod v4 `_zod` schema + 完整反射 ③改官方 api-remotes 或等价 `$mount` ④过 agent-lookup gateway。为"读几个 taste.md 文件"付出这套脆弱且无文档的机器，是明显的错误工具。

### 0.3 B 可用的排他性证据（源码）

B 是 `connection` 服务上**公开的、零生成、零 schema 的泛化 RPC 通道注册点**：

**(a) host 面注册面（开放）：** `<web>/dsh-client-connection/lib/index.js`：

- `:219-225` `get rpc()` 返回 `{ handle, intercept }`，`handle` 即 `(channel, handler, options) => this.register(owner, channel, handler, options)`。
- `:241-258` `register(owner, channel, handler, options)`：`options.authority === "loopback"` 时 `trustedHosts = []`（loopback-only 栅栏，见 `:190-200` `isTrustedApiRequest` + `:91-109` `isLoopbackHostname`），然后 `owner.effect(() => owner.webServer.register(route), ...)` 注册一条 `{ kind:"prefix", path:channel }` 路由。
- `:275-301` `rpcFetchHandler`：仅 `POST`、仅 JSON、`clientRequestSchema.safeParse` 校验信封、校验 `message.method === endpoint`，最后 `await handler(endpoint, message.payload, request.signal)`。
- `:322-329` `fullResponse(rpcId, result)` 把 handler 返回值包成 `{ type:"server-response", rpcId, result }`——即 handler 返回 `{ok:true,value}|{ok:false,error}`。
- `:203-204` `CHANNEL_PATTERN = /^\/[A-Za-z0-9._~-]+$/`、`ENDPOINT_SEGMENT_PATTERN = /^[A-Za-z0-9_$.-]+$/`（`"/taste"` 合法；endpoint 单段合法）。
- `:479` 本插件 `inject = ["webServer"]`，`:588` 导出 `HostConnectionService`。

**`connection` 服务确实在本 profile 被装载**：`<web>/dsh-web-app/cordis.patch.yml:165-171` `- id: connection  name: '@deepseek-ai/dsh-client-connection'  inject: [webRuntime]  config: { trustedHosts: ... }`。故 dsh-taste 只需 `inject: [...现有, "connection"]` 即可在 `apply` 里 `ctx.connection.rpc.handle(...)`。

**(b) client 面调用句柄（开放）：** `<web>/dsh-client-connection/lib/client.js`：

- `:10257` `const inject = []`（线缆根）。
- `:10262-10315` `apply(ctx)` 末尾 `ctx.provide("connection", handle)`，`handle = { api, isLoopback, hostDescription:{getSnapshot,subscribe}, rpc, start }`（`:10280-10314`）。
- `:10206-10227` `createWebConnectionRpc` → `rpc.call(channel, endpoint, payload, signal)`：`POST ${channel}/${endpoint}`，信封 `{type:"client-request", rpcId, method:endpoint, payload}`，返回 `full.result`（即 host 的 `{ok,value|error}`）。

> 对比 A/B：A 的 `ctx.remote.taste.*` 是 `api.<ns>.<method>` 编译闭集的一支（api-remotes 编译进去的）；B 的 `rpc.call(channel,endpoint,payload)` 是**第三方插件可用的开放入口**（报告 B §1.2/§6 已确认，此处源码复核一致）。

### 0.4 决定性裁定句

> 自装插件（无构建、无 typert 生成器）在 client 半**实际可用的数据调用句柄**是 `ctx.get("connection").rpc`（`rpc.call(channel, endpoint, payload)`），配 host 半 `ctx.connection.rpc.handle("/taste", handler, {authority:"loopback"})`。A 的 `ctx.remote.taste.*` 需要 `dsh-typert-generator` 产物 + 官方 api-remotes 编译描述符 + agent-lookup gateway，三条在本环境均不具备/不可触碰，故**排他性选定 B**。

## 1. 发现链路终稿

### 1.1 机制一句话

浏览器不扫 node_modules。client 插件由 host 半 `dsh-client-modules`（`ClientModuleRegistry`）扫描「已被 cordis Loader 装载的条目」：凡 package.json 有 `dsh.client`（`platform:"web"`）且 `exports["./client"]` 指向存在的 bundle，就编入 `window.__DSH_BOOT__`，经 `/plugins/<id>/client.js` 动态 `<script>` 注入（`<web>/dsh-client-modules/lib/index.js:290-303` 构造器、`:459-490` `serveBundle`、`:209-250` `bootInjections`）。

### 1.2 dsh-taste package.json 精确增量

当前 `<taste>/package.json` 只有 `main`/`peerDependencies`。需要加入两处（终稿）：

```jsonc

  "type": "module",
```

### 1.3 校验规则对照（`parseDshClient` / `clientExportOf`）

- `parseDshClient`（`<web>/dsh-client-modules/lib/index.js:120-134`）：`dsh.client` 必须是对象；`platform` 必须为字符串；`inject`/`external` 为**字符串数组**；`immediately` 布尔。`resolveMeta`（`:377-404`）在 `:390` 检查 `decl.platform !== "web"` → 返回 `null`（不进入 browser roster）。
- `clientExportOf`（`:136-146`）：`exports["./client"]` 接受 `"字符串"` 或 `{ "default": "字符串" }` 一阶条件导出。上面的 `{ "types": ..., "default": "./lib/client.js" }` 满足（取 `default`）。
- **必须同时提供 `"./package.json"`**：`resolveMeta` 靠 `this.resolvePkgJson = (spec) => require.resolve(\`${spec}/package.json\`)`（`:276`）读包元数据。一旦加 `exports` 而未放行 `./package.json`，`require.resolve` 抛 `ERR_PACKAGE_PATH_NOT_EXPORTED`，`resolveMeta` 捕获后返回 `null`（`:383-386`）→ **client 半静默不被发现**。已装官方双面包全部带 `"./package.json":"./package.json"`（见 1.4）。

### 1.4 "." 映射不破坏 host 半 main 解析的验证

官方双面包的模式（dsh-taste 照抄即安全）：

| 包 | `main` | `exports["."]` | 证据 |
|---|---|---|---|
| `dsh-client-connection` | `lib/index.js` | `{ types, default: "./lib/index.js" }` | `<web>/dsh-client-connection/package.json` |
| `dsh-client-modules` | `lib/index.js` | 同上 | `<web>/dsh-client-modules/package.json` |
| `dsh-client-ui-goal` | `lib/index.js` | 同上 | `<web>/dsh-client-ui-goal/package.json` |

dsh-taste 当前 `main: "lib/index.js"`；新增 `exports["."].default = "./lib/index.js"` 后，`require.resolve("@deepseek-ai/dsh-taste")` 与 `import "@deepseek-ai/dsh-taste"` 仍落到 `lib/index.js`（Node ESM exports 优先但路径一致）。host 半 Loader 以 `entry.options.name`（包名，`<web>/dsh-client-modules/lib/index.js:290` `ctx.loader.entries()` → `entry.options.name`）解析包入口，不受 exports 影响；唯一新增风险是 `./package.json` 未放行（1.3 已覆盖）。

### 1.5 client bundle 到达与 `dsh.client.inject` 语义（澄清两层 inject）

**两层 inject 必须区分，否则 bundle 不被激活或排序错乱：**

1. **package.json 的 `dsh.client.inject` = 包名数组**（bundle 激活前需先装载哪些其他 client bundle）。实证：`<web>/dsh-client-runtime/package.json` 的 `dsh.client.inject = ["@deepseek-ai/dsh-client-connection","@deepseek-ai/dsh-typert-registry","@deepseek-ai/dsh-api-remotes"]`；`<web>/dsh-client-ui-goal/package.json` 的 `dsh.client.inject` 也是包名。→ 1.2 里写运行时/locale/connection 三个包名正确。
2. **bundle 工厂 `exports.inject` = 服务名数组**（cordis fiber 的 inject gating，决定 `apply(ctx)` 何时跑、`ctx.<service>` 可访问）。见 §3。

`react`、`react/jsx-runtime`、`react-dom`、`@deepseek-ai/dsh-client-ui-primitives`、`@deepseek-ai/dsh-client-ui-slots` 是 **seed word**（编译进 Vite shell dist），既不需要 `dsh.client.inject` 也不需要 `external`，经 `makeRequire` 的 seed 分支解析（`<web>/dsh-client-modules/lib/client.js:251-261`）。

## 2. host 半桥接（`lib/bridge.js` 新文件）

### 2.1 注册时机与生命周期

- **时机：在 `apply()` 内直接调用**（不等待"服务就绪"）。`connection` 是 cordis inject 依赖，`apply` 运行时已保证存在（`inject` gating）。`rpc.handle` 内部用 `connection` 服务自身 ctx 做 `webServer.register`（`:241-258`），无额外 ready 等待。
- **生命周期：** `rpc.handle` 返回 `owner.effect(...)` 的 disposer（`register` 返回 `owner.effect(...)`，`:256-257`）。显式把它挂到 dsh-taste 自己的 effect 上，卸载时反注册：
  ```js
  const dispose = ctx.connection.rpc.handle("/taste", handle, { authority: "loopback" });
  ctx.effect(() => dispose, "taste.rpc.channel");
  ```
  （不写显式 disposer 也能跑——路由默认随 connection 插件同生命周期；但显式绑定到 taste 更正确，且便于 node:test 断言。）

### 2.2 bridge.js 完整接口设计

```js
// <taste>/lib/bridge.js  （ESM，host 半，只读）
import { statSync } from "node:fs";
import { join, resolve } from "node:path";

const ENDPOINTS = new Set(["getTree", "getStatus"]);

function describeError(error) {
  return error instanceof Error ? error.message : String(error);
}

// deps 形状由 index.js 注入（见 2.4），全部走 storage.js 白名单函数。
export function registerTasteBridge(ctx, deps) {
  const { currentConfig, queue, globalDir, projectDirForCwd,
          listTasteFiles, readTasteFile, parseTasteFile, loadCommandCodeTaste } = deps;

  const handle = async (endpoint, payload, signal) => {
    if (!ENDPOINTS.has(endpoint)) {
      return { ok: false, error: { code: "unknown-endpoint", message: `taste: unknown endpoint "${endpoint}"` } };
    }
    try {
      if (endpoint === "getTree") return { ok: true, value: await getTree(payload ?? {}) };
      if (endpoint === "getStatus") return { ok: true, value: getStatus() };
    } catch (error) {
      return { ok: false, error: { code: "internal", message: describeError(error) } };
    }
  };

  // ---- 只读数据装配（全部白名单函数，无 path 直通、无原始字节） ----
  async function scopeFiles(dir) {
    const files = [];
    for (const relPath of await listTasteFiles(dir)) {           // storage.js:202
      let content;
      try { content = await readTasteFile(dir, relPath); }        // storage.js:191 (resolveTastePath 白名单)
      catch { continue; }                                        // 单文件失败跳过，不整树失败
      const entries = parseTasteFile(content);                    // storage.js:117 → {statement, confidence}[]
      let mtime = 0;
      try { mtime = statSync(join(dir, relPath)).mtimeMs; } catch {}
      files.push({ relPath, mtime, count: entries.length, entries });
    }
    return files;
  }

  async function getTree({ cwd }) {
    const global = globalDir();                                  // index.js:335 dshHomePath("taste")
    const project = typeof cwd === "string" && cwd.length > 0 ? projectDirForCwd(cwd) : void 0; // index.js:336
    const globalHome = resolve(global, "..", "..");              // 与 loadTasteSnapshot 同算法 (storage.js:492)
    const projectRoot = project ? resolve(project, "..", "..") : void 0;   // storage.js:494
    const commandCodeEntries = await loadCommandCodeTaste(globalHome, projectRoot); // storage.js:423
    return {
      generatedAt: Date.now(),
      scopes: [
        { name: "project", dir: project ?? null, present: project !== void 0,
          files: project ? await scopeFiles(project) : [] },
        { name: "global", dir: global, present: true, files: await scopeFiles(global) },
        { name: "commandCode", dir: null, present: true,
          files: [{ relPath: "(command-code)", mtime: 0, count: commandCodeEntries.length,
                    entries: commandCodeEntries }] },
      ],
    };
  }

  function getStatus() {
    const cfg = currentConfig();                                 // index.js:370 白名单合并后的热读配置
    const q = queue.stats();                                     // queue.js:144 {pending,failCount,cooldownUntil,running}
    return {
      learning: cfg.learningEnabled,
      injection: { enabled: cfg.injection.enabled, maxChars: cfg.injection.maxChars,
                   includeSubagents: cfg.injection.includeSubagents },
      modelMode: cfg.observer.modelMode,                         // "inherit" | "custom"（不回显 provider/model 名）
      queue: q,
      breakerCooling: q.cooldownUntil > Date.now(),
    };
  }

  const dispose = ctx.connection.rpc.handle("/taste", handle, { authority: "loopback" });
  ctx.effect(() => dispose, "taste.rpc.channel");
}
```

### 2.5 明确拒绝清单（安全红线）

- **无 `path` 参数直通**：`getTree` 只接受可选 `cwd`（字符串，仅用于 `projectDirForCwd` 解析项目目录）；`getTree`/`getStatus` 的 payload **不存在** `file`/`dir`/`relPath` 形参，客户端无法要求读取任意路径。
- **无原始字节**：只返回 `parseTasteFile` 的 `{statement, confidence}` 结构化 JSON + 每文件 `mtime`/`count` 元数据，**不返回** `readTasteFile` 的原始 markdown 文本、不返回 `renderTasteFile` 文本、不返回任何文件字节。
- **只读 loopback**：`{ authority: "loopback" }` 使 `trustedHosts = []`（`<web>/dsh-client-connection/lib/index.js:241-243`），所有非 loopback 源被 `isTrustedApiRequest` 栅栏拒绝（`:190-200`）；`webServer` 本身绑 `127.0.0.1`（`<web>/dsh-web-app/cordis.patch.yml:118-125` `host: '127.0.0.1'`）。
- **无写操作**：bridge 不暴露 `writeFileAtomicTaste` / `withTasteLock` / `saveConfig`，forget/remember 只留在 `/taste` 命令。

## 4. UI 设计

### 4.1 信息架构

```
TasteTrigger（sidebar.footer.action 图标按钮，order≈90，tooltip=trigger）
  └─ 点击 → store.toggle()
TastePanel（shell.overlay 全屏浮层，closed 渲染 null）
  ├─ Header：标题 + 学习状态条 + [刷新按钮] + [关闭]
  ├─ 状态条：learning on/off · injection(≤N) · queue(pending/state) · breaker(cooling/armed) · modelMode
  └─ Body：
      ├─ 分源 Tab：[全局] [项目] [Command Code]   （scope.name；project present:false 时灰显/隐藏）
      └─ 每个 Tab：
          ├─ 文件折叠列表（scope.files，按 relPath 折叠）
          │    └─ 每个文件展开 → 条目列表 entries[]（statement + confidence 可视化条）
          ├─ 空态 empty / empty.all
          └─ 错误态 error.load
```

- **分类目录**：taste 文件的分类目录（`relPath` 形如 `style/taste.md`、`security/taste.md`）→ 用 `relPath` 的目录段做**二级折叠**（"category → file → entries"）。M0 可先按 `relPath` 平铺折叠；分类折叠是纯前端分组（不新增 host 字段）。
- **置信度可视化**：`confidence ∈ [0,1]` → 每条目一个 0–100% 水平条（颜色用 `--dsw-alias-state-*` token；≥0.7 绿、0.4–0.7 黄、<0.4 灰，参考 cordis 状态色 `<web>/dsh-client-ui-cordis/lib/client.js:572` 的 `state-success/warn/error` token 用法）。
- **刷新**：手动刷新按钮 + `setInterval` 10s 轮询（`getStatus` + `getTree` 并行；`getTree` 有 mtime 缓存，成本极低——host 侧 `createSnapshotReader` `<taste>/lib/index.js:250` 已是 mtime 门控；本 bridge 的 `getTree` 每次 `listTasteFiles`+`readTasteFile`+`parseTasteFile`，文件数极少）。轮询仅在面板 open 时运行，close/unmount 清 timer。
